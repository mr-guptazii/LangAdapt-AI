# Contributing

## Setup

See the Quick Start in [README.md](../README.md). For active development, Option B (native, with `--reload`) is faster to iterate on than Docker.

## Code style

- **Backend**: `ruff` (config in `apps/api/ruff.toml`) for lint + import sorting. Run `make lint` / `make format`. Type hints throughout; `mypy` is listed as a dev dependency but not yet wired into CI as a blocking check — feel free to tighten this.
- **Frontend**: ESLint (`next/core-web-vitals` + `next/typescript`), strict TypeScript (`noUncheckedIndexedAccess` on). Run `npx eslint .` / `npx tsc --noEmit`.
- Keep functions small and files under a few hundred lines — see `app/agents/nodes/` for the pattern of splitting by responsibility rather than one giant file.
- Comments explain *why*, not *what* — see existing docstrings for the tone (e.g. `app/learning/spaced_repetition.py`'s module docstring explaining why SM-2 was chosen over full FSRS).

## Adding a new agent node

1. Add the node function to the appropriate file under `app/agents/nodes/` (or a new file if it's a new responsibility).
2. If it needs DB access, accept `db: AsyncSession` as a parameter and wire it into `graph.py::build_tutor_graph` via a small async wrapper (**not a lambda** — see the comment in `graph.py` explaining why lambdas around async functions silently break LangGraph).
3. Add any new state fields to `app/agents/state.py::TutorState`.
4. If it calls an LLM, add a prompt builder under `app/ai/prompts/` and a matching schema in `app/schemas/agent_io.py`.
5. Update the mock provider (`app/ai/providers/mock_provider.py`) if the new schema needs realistic mock content to keep the no-API-key demo path meaningful.

## Adding a new target language

Add `app/learning/languages/<code>/grammar_topics.py` mirroring `en`'s shape, register it in `app/learning/curriculum.py::CURRICULUM_BY_LANGUAGE`, and seed its `Skill` rows in `scripts/seed.py`.

## Database changes

Always via Alembic — never hand-edit the schema. `alembic revision --autogenerate -m "description"` after changing a model in `app/models/`, then review the generated file before committing (autogenerate is a starting point, not gospel — see how migration `a1b2c3d4e5f6` was hand-split from the autogenerated output for a real example).

## Tests

Add unit tests alongside new deterministic logic (mastery/SRS/routing — see `tests/`) and extend the mock provider's special-cased fields so new agent outputs are demoable without an API key. See [TESTING.md](TESTING.md) for the current coverage and known gaps.
